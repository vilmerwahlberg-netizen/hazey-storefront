# Design workflow

## Shape

1. Gather durable product truth, constraints, real content, current renders, and reference evidence.
2. State the visitor mode and the primary conversion path.
3. Produce 2–3 structurally distinct concepts. Keep content constant.
4. For each concept, show mobile and desktop, explain the focal hierarchy, section rhythm, image system, and motion thesis.
5. Stop for human selection. No production edits.

## Redesign

1. Confirm which visual world is rejected and which facts/functions remain.
2. Treat old styling as anti-reference, not a system to polish.
3. Translate the selected concept into a compact direction contract: type roles, palette distribution, spatial rules, surface types, imagery, motion, responsive composition, and anti-goals.
4. Prototype the highest-risk first viewport and one mid-page rhythm transition before rebuilding the whole page.
5. Obtain visual acceptance, then implement in bounded component groups.

## Refine

1. Name the target and visible defect.
2. Identify the owning source and competing native rules.
3. Make the strongest scoped correction.
4. Render before/after at affected widths.
5. Run interaction and regression checks after the visual result holds.

## Critique

Return:
1. Three highest-impact visual problems.
2. Concrete rendered evidence for each.
3. Why each affects brand, comprehension, trust, or conversion.
4. A prioritized correction, not a vague adjective.
5. Deliberate differences and constraints that should remain.

Do not implement during a critique-only request.

## Motion

Write a short motion thesis first: focal moment, continuity, feedback, performance budget. Prototype and record the highest-risk interaction. Obtain acceptance before distributing motion across the page.

## Cost control

Use one inspection pass, one batched correction pass, and one confirmation pass. Do not spend hours repeatedly updating snapshots while the human has not accepted the direction. A fresh golden baseline records an accepted result; it does not prove one.
